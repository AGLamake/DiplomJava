# Информационная система охранного агентства

Веб-приложение для мониторингового центра охранного агентства, которое охраняет недвижимость и автомобили.
Проект — перенос дипломного приложения «Информационная система охранного агентства» с C# / WinForms / MS SQL Server
на **Java 21 + Jakarta Faces (JSF) 4.0 + PrimeFaces + PostgreSQL**; работает в Apache Tomcat 10.1, открывается в браузере.
В новой версии добавлено разграничение прав по ролям, а тревоги и выезды сохраняются в БД.

Код приложения лежит в папке [`security-agency/`](security-agency/).

## Возможности

**Учётные записи**
- Регистрация и вход по логину и паролю. Пароли хранятся как хэш PBKDF2-HMAC-SHA256 с солью.
- Первый зарегистрированный пользователь становится администратором. Остальные регистрируются как операторы
  и могут войти только после того, как администратор включит учётную запись.
- Администратор назначает роли, блокирует пользователей и сбрасывает пароли.

**Мониторинг охраняемых объектов**
- **Автомобиль:** схема машины с датчиками (капот, передняя и задняя двери, багажник, АКБ, зажигание),
  постановка и снятие с охраны, глушение двигателя.
- **Недвижимость:** схема квартиры с датчиками ИК (движение), СМК (открытие двери), ДРС (разбитие стекла),
  ДИП (пожар), ДУВ (протечка воды), ДУГ (утечка газа) и КТС (тревожная кнопка), а также вызов МЧС.
- **Автоматический вызов ГБР:** при третьем срабатывании датчиков или сразу после нажатия КТС приложение отправляет
  первую свободную группу быстрого реагирования. Время до прибытия ГБР и МЧС отсчитывается на экране.
- **Журнал событий** на экране мониторинга. Каждое срабатывание записывается в таблицу `alarm_events`
  (для автомобиля — с последними GPS-координатами), каждый выезд — в `dispatches`.

**Тревоги и выезды**
- Оператор видит все события и выезды, завершает выезд с результатом (проникновение подтверждено,
  ложная тревога, нет доступа, иное) и отмечает событие без выезда как ложную тревогу.
- Сотрудник ГБР видит выезды своей группы, отмечает прибытие и завершает выезд.

**Справочники** (поиск по любой колонке, добавление, изменение, удаление)
- Клиенты (физические и юридические лица), объекты недвижимости, автомобили.
- Договоры с привязкой нескольких объектов клиента.
- Группы быстрого реагирования и их состав.
- Установленное оборудование и заявки на монтаж.
- Журнал действий пользователей: вход, регистрация, постановка и снятие охраны, глушение, вызовы, изменения учётных записей.

## Роли и права доступа

| Раздел | Администратор | Менеджер | Инженер | Оператор | Сотрудник ГБР |
|---|:-:|:-:|:-:|:-:|:-:|
| Автомобиль / Недвижимость (мониторинг) | ✎ | — | — | ✎ | — |
| Тревоги и выезды | ✎ | 👁 | — | ✎ | 👁 |
| Клиенты, объекты недвижимости, автомобили | ✎ | ✎ | 👁 | 👁 | — |
| Договоры | ✎ | ✎ | — | 👁 | — |
| ГБР | ✎ | 👁 | — | 👁 | 👁 |
| Оборудование | ✎ | 👁 | ✎ | 👁 | — |
| Заявки на монтаж | ✎ | ✎ | ✎ | — | — |
| Мои выезды | — | — | — | — | ✎ |
| Пользователи | ✎ | — | — | — | — |
| Журнал действий | 👁 | — | — | — | — |

✎ — просмотр и изменение, 👁 — только просмотр, — — раздел скрыт.
Права проверяются и на сервере: страница раздела без права просмотра отвечает «403 Доступ запрещён»,
а действия без права изменения отклоняются.
Роль «Клиент» есть в БД, но войти в приложение с ней нельзя.

## Быстрый старт

```powershell
# 1. Клонировать репозиторий
git clone https://github.com/AGLamake/DiplomJava.git
cd DiplomJava\security-agency

# 2. Переключить консоль на UTF-8, чтобы сообщения psql читались (иначе русский текст ошибок будет «кракозябрами»)
chcp 65001

# 3. Создать базы данных и загрузить схему (пароль пользователя postgres спросит psql)
#    Порядок важен: сначала 01_schema.sql (таблицы), потом 02_seed.sql (данные)
psql -U postgres -c "CREATE DATABASE security"
psql -U postgres -c "CREATE DATABASE security_test"
psql -U postgres -d security -1 -f sql/01_schema.sql
psql -U postgres -d security -1 -f sql/02_seed.sql     # демонстрационные данные (необязательно)

# 4. Настроить подключение
copy src\main\resources\db.properties.example src\main\resources\db.properties
notepad src\main\resources\db.properties               # указать пароль postgres

# 5. Запустить (первый раз Maven скачает Tomcat) и открыть http://localhost:8080/security-agency/
mvn package cargo:run
```

Остановить сервер — `Ctrl+C` в окне, где он запущен.

Если `psql` не находится, укажите полный путь, например
`& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres ...`.

> **Кодировка.** Оба SQL-скрипта сохранены в UTF-8 и начинаются с `SET client_encoding = 'UTF8'`,
> поэтому кириллица попадёт в базу правильно при любой кодировке консоли. Команда `chcp 65001`
> нужна только для того, чтобы сообщения psql (в том числе ошибки) читались в консоли, а не превращались в
> «Р?РЁР?Р'Р?Р?». Её нужно выполнять в каждом новом окне PowerShell.

После запуска нажмите «Регистрация» и создайте первого пользователя — он станет администратором.

## Настройка

### Подключение к БД — `db.properties`

```properties
db.url=jdbc:postgresql://localhost:5432/security
db.user=postgres
db.password=ваш_пароль
```

Приложение ищет настройки в таком порядке:
1. Файл, указанный системным свойством JVM `security.db`. Для `mvn cargo:run` по умолчанию это
   `security-agency/db.properties`, другой файл можно задать так: `mvn cargo:run -Dsecurity.db=D:\conf\db.properties`.
   Для отдельного Tomcat свойство задаётся в `bin\setenv.bat`: `set CATALINA_OPTS=-Dsecurity.db=D:\conf\db.properties`.
   Если свойство не задано, берётся `db.properties` из рабочей папки Tomcat.
2. `src/main/resources/db.properties`, вложенный в war (`WEB-INF/classes`).

Файлы `db.properties` исключены из git, чтобы пароль не попал в репозиторий.

### Время прибытия служб — `src/main/resources/app.properties`

```properties
dispatch.eta.seconds=900   # ГБР, по умолчанию 15 минут
mchs.eta.seconds=900       # МЧС
```

Для демонстрации удобно поставить 20–30 секунд.

### Тестовая база — `src/test/resources/db-test.properties`

```properties
db.url=jdbc:postgresql://localhost:5432/security_test
db.user=postgres
db.password=postgres
```

Тесты **пересоздают схему** в этой базе перед каждым тестом. Никогда не указывайте здесь рабочую базу.

## Запуск и сборка

Все команды выполняются из папки `security-agency`.

| Задача | Команда |
|---|---|
| Запуск в Tomcat из исходников | `mvn package cargo:run` → http://localhost:8080/security-agency/ |
| То же без тестов | `mvn -DskipTests package cargo:run` |
| Все тесты | `mvn test` |
| Один тестовый класс | `mvn test -Dtest=MonitorBeanTest` |
| Сборка war | `mvn -DskipTests package` → `target/security-agency.war` |

**Развёртывание на своём Tomcat 10.1.** Скопируйте `target/security-agency.war` в папку `webapps` Tomcat
и задайте путь к настройкам БД (см. «Подключение к БД»). Приложение откроется по адресу
`http://сервер:8080/security-agency/`. Нужен именно Tomcat 10.1+ (пространство имён `jakarta.*`);
Tomcat 9 и старше не подойдут.

## Как проверить

Все команды выполняются из папки `security-agency`, PostgreSQL должен быть запущен.

### 1. Автотесты

```powershell
mvn test
```

Ожидаемый результат: `Tests run: 172, Failures: 0, Errors: 0` и `BUILD SUCCESS`. Подробнее — в разделе [Тесты](#тесты).

### 2. Запуск сервера

```powershell
mvn -DskipTests package cargo:run
```

Сервер готов, когда в консоли появится `Press Ctrl-C to stop the container...`. Откройте
http://localhost:8080/security-agency/ — должна открыться страница «Авторизация».

Чтобы таймеры ГБР и МЧС не ждать 15 минут, перед запуском поставьте в `src/main/resources/app.properties`
`dispatch.eta.seconds=30` и `mchs.eta.seconds=30`.

Чтобы проверить на чистой базе, не трогая рабочую, создайте отдельную базу, загрузите в неё `sql/01_schema.sql`
и `sql/02_seed.sql`, положите файл настроек с её адресом, например `D:\conf\db-check.properties`, и запустите
`mvn -DskipTests package cargo:run -Dsecurity.db=D:\conf\db-check.properties`.

## Пример работы

1. **Первый вход.** Откройте http://localhost:8080/security-agency/, зарегистрируйте пользователя `admin` —
   он станет администратором. Войдите.
2. **Новый оператор.** Зарегистрируйте `operator` (выход → «Регистрация»). Под `admin` откройте
   «Пользователи», выберите `operator`, нажмите «Изменить», отметьте «Активен» и сохраните.
3. **Тревога по автомобилю.** Войдите как `operator` → «Автомобиль» → выберите `[4] Ford Fusion (М117РН)`.
   Нажмите «Капот», «Передняя дверь», «Задняя дверь». В журнале появятся записи:
   ```
   29.10.2026 20:25:48 : Подкапотное пространство: Срабатывание датчика взлома №1. Автомобиль [[4] Ford Fusion (М117РН)].
   29.10.2026 20:25:48 : Передние двери: Срабатывание датчика удара №2. Автомобиль [[4] Ford Fusion (М117РН)].
   29.10.2026 20:25:48 : Задние двери: Срабатывание датчика удара №3. Автомобиль [[4] Ford Fusion (М117РН)].
   29.10.2026 20:25:48 : Множественное срабатывание датчиков: [3]. Автомобиль [[4] Ford Fusion (М117РН)].
   29.10.2026 20:25:48 : ГБР: Группа Быстрого Реагирования отправлена [Операторов О.О.]. Автомобиль [[4] Ford Fusion (М117РН)].
   ```
   Через заданное время ГБР «прибудет», и в журнале появится запись о прибытии. Отсчёт идёт по реальному
   времени и не сбрасывается при переходе в другие разделы, пока открыта любая страница приложения.
4. **Тревожная кнопка.** «Недвижимость» → объект → «КТС»: ГБР отправляется сразу.
   «Вызвать МЧС» запускает отдельный отсчёт.
5. **Завершение выезда.** «Тревоги и выезды» → строка с выездом → «Завершить выезд» → результат
   «Ложная тревога». Группа снова свободна, объект снова под охраной.
6. **Справочники.** «Автомобили» → «Добавить» → Renault Logan, номер Т843СТ → «Сохранить».
   Поиск понимает любой регистр: `т843ст` найдёт запись.

## Тесты

```powershell
mvn test
```

Нужен запущенный PostgreSQL с базой `security_test`. Набор из 172 тестов:

- **Модульные:** матрица прав, фильтр доступа к страницам, хэширование паролей, логика мониторинга
  (`MonitoringSession`: датчики, автовызов ГБР, таймеры, МЧС), разбор ввода в формах, поиск.
- **Интеграционные с БД:** все DAO, вход и регистрация, тревоги и выезды (в том числе ситуация «нет свободной ГБР»),
  внешние ключи и уникальность.
- **Веб-слой (бины JSF без контейнера):** вход и регистрация, добавление/изменение/удаление через форму,
  сообщения об ошибках проверки, доступ только на чтение, договоры и объекты клиента, сброс пароля,
  действия в «Тревогах» и «Моих выездах», сценарий мониторинга от датчиков до прибытия ГБР
  (с «догоняющим» таймером) с проверкой записей в БД.

Тесты не запускают Tomcat: зависимости бинов подставляются вручную, а сообщения пользователю записываются
подменённым `FacesUi`. Не запускайте `mvn test`, пока `mvn cargo:run` работает с той же базой `security_test`.

> Не запускайте тесты одновременно из двух мест (например, из терминала и IntelliJ IDEA):
> они пересоздают одну и ту же тестовую базу и мешают друг другу.

## Структура проекта

```
DiplomJava/
├── README.md                     этот файл
├── docs/superpowers/plans/       план переноса с WinForms на Java
└── security-agency/
    ├── pom.xml                   packaging war, Tomcat через cargo
    ├── sql/
    │   ├── 01_schema.sql         схема БД (PostgreSQL)
    │   └── 02_seed.sql           демонстрационные данные
    ├── tools/make_scheme_images.py
    └── src/
        ├── main/java/ru/vlsu/security/
        │   ├── AppContext.java   все DAO и сервисы
        │   ├── config/       подключение к БД (HikariCP), app.properties
        │   ├── security/     роли, разделы, матрица прав, PasswordHasher
        │   ├── model/        record-классы сущностей и статусы
        │   ├── dao/          JDBC-доступ к таблицам, перевод ошибок БД в понятный текст
        │   ├── service/      вход/регистрация, пользователи, тревоги, выезды ГБР, журнал действий
        │   ├── monitoring/   MonitoringSession — датчики и таймеры без UI и БД
        │   ├── validation/   проверка ввода в формах
        │   └── web/          JSF-бины и инфраструктура:
        │                       AppResources (пул и сервисы), UserSession, AuthFilter (доступ к страницам),
        │                       TableBean/CrudBean (общая таблица и форма), бины разделов, MonitorBean
        ├── main/webapp/
        │   ├── *.xhtml           страницы: вход, разделы, мониторинг (car/ndv), ошибка
        │   ├── WEB-INF/templates layout.xhtml (шапка и меню), table.xhtml (таблица + диалог формы)
        │   ├── WEB-INF/includes  экран мониторинга, диалог завершения выезда
        │   ├── WEB-INF/          web.xml, beans.xml, faces-config.xml
        │   └── resources/        CSS, JS, картинки схем машины и квартиры
        ├── main/resources/   настройки (db.properties, app.properties)
        └── test/             JUnit 5: модульные, интеграционные тесты и тесты бинов
```

Слои: страницы `*.xhtml` → бины `web` → `service` → `dao` → PostgreSQL. Вся логика мониторинга сосредоточена
в `monitoring/MonitoringSession`: этот класс не зависит от JSF и БД, поэтому его проверяют обычные модульные тесты.
Бин `MonitorBean` живёт всю HTTP-сессию и раз в секунду (`p:poll`) «догоняет» таймеры ГБР/МЧС по реальному времени.

## Частые проблемы

| Симптом | Решение |
|---|---|
| Страница «Сервис недоступен: Не удалось подключиться к базе данных» | Проверьте, что PostgreSQL запущен и в `db.properties` указаны верные адрес, пользователь и пароль. Перезапускать Tomcat не нужно — подключение проверяется заново при следующем запросе |
| `mvn cargo:run`: `Address already in use` / порт 8080 занят | Порт занят другим сервером (или прошлым запуском). Остановите его либо задайте другой порт: `mvn cargo:run -Dhttp.port=8081` |
| «Учётная запись ожидает активации администратором» | Администратор должен отметить пользователя «Активен» в разделе «Пользователи» |
| «Нет свободных групп быстрого реагирования» | Все ГБР на выездах. Завершите выезд в «Тревоги и выезды» или добавьте группу в разделе «ГБР» |
| «Запись используется в других таблицах и не может быть удалена» | На запись ссылаются другие данные (например, у клиента есть договоры). Сначала удалите или измените их |
| Тесты падают с `duplicate key ... pg_class` | Тесты запущены одновременно в двух местах. Дождитесь окончания одного прогона |
| psql выводит ошибки «кракозябрами» (`Р?РЁР?Р'Р?Р?: ...`) | Выполните `chcp 65001` в этом окне PowerShell и повторите команду. На данные в базе это не влияет |
| `отношение "clients" не существует` при загрузке `02_seed.sql` | Таблиц ещё нет: сначала выполните `01_schema.sql`, потом `02_seed.sql` |
| `отношение "roles" уже существует` при загрузке `01_schema.sql` | Схема уже загружена. Чтобы начать с нуля: `psql -U postgres -c "DROP DATABASE security"`, затем создать базу и загрузить оба скрипта заново |
